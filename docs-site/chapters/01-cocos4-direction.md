# 01. COCOS 4의 방향

루트 `README.md`는 COCOS 4를 공개 고성능 크로스플랫폼 게임/인터랙티브 콘텐츠 엔진으로 설명합니다. 중요한 변화는 “Cocos Creator”라는 이름 아래 묶여 있던 엔진과 에디터를 분리하고, 엔진 자체를 COCOS 4로 정리하려는 점입니다.

## 핵심 변화

COCOS 4의 방향은 다음 세 가지로 읽을 수 있습니다.

- 엔진은 독립 오픈소스 프로젝트로 더 명확해진다.
- 에디터 핵심 부품과 크로스플랫폼 프레임워크가 CLI 도구와 엔진 기능으로 이동한다.
- AI 통합을 전제로, 사람이 GUI에서만 조작하던 작업을 스크립트와 도구 호출로 재구성할 수 있게 한다.

이 변화는 게임 개발자에게 의미가 큽니다. 에디터 화면을 누르는 것만 자동화하는 수준이 아니라, 엔진이 가진 빌드, 에셋, 씬, 렌더링, 프리뷰 기능을 명령형 도구로 다룰 수 있어야 AI 제작 루프가 안정됩니다.

## 기존 Cocos Creator와의 차이

기존 Creator 경험은 에디터 중심입니다. 프로젝트를 만들고, 노드를 배치하고, 컴포넌트를 붙이고, 프리뷰를 실행하는 흐름이 UI에 강하게 묶여 있습니다.

COCOS 4가 지향하는 방향은 엔진과 도구의 경계를 더 명확히 하는 것입니다. 루트 README는 “core components of the editor will be converted to CLI tools and integrated into the engine's core functionality”라고 설명합니다. 이 문장은 에디터 기능을 버린다는 뜻이 아니라, 에디터 기능을 자동화 가능한 표면으로 옮긴다는 뜻에 가깝습니다.

## AI 시대의 엔진 조건

AI가 게임 제작에 실제로 도움이 되려면 다음 조건이 필요합니다.

- 입력은 명시적인 도구 호출이어야 한다.
- 결과는 파일, 로그, 씬 상태, 프리뷰 상태로 검증되어야 한다.
- 실패는 가짜 성공으로 덮지 않고 그대로 노출되어야 한다.
- 에셋 생성, 카탈로그 등록, 타임라인 삽입, 빌드 동기화가 하나의 추적 가능한 흐름이 되어야 한다.

이 포크의 문서는 이런 관점으로 COCOS 4를 읽습니다. 엔진 자체의 공식 기능과, 우리가 게임 제작 경험에서 얻은 자동화 요구를 구분하되, 두 흐름이 만나는 지점을 계속 기록합니다.

## 확인 경로

- `README.md`: COCOS 4의 공개 방향과 기능 요약.
- `package.json`: CLI 빌드 스크립트와 버전.
- `scripts/`: 빌드, declaration, adapter, native pack tool.
- `native/`: C++ 런타임과 플랫폼 계층.
- `exports/`: TypeScript public entrypoint.
