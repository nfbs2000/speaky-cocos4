# 15. CLI와 Editor 분리

COCOS 4 README에서 가장 중요한 문장 중 하나는 에디터 핵심 구성 요소를 CLI 도구로 전환하고 엔진 핵심 기능에 통합한다는 내용입니다. 이 방향은 AI 게임 개발과 직접 연결됩니다.

## 확인 경로

- `scripts/`
- `scripts/native-pack-tool`
- `platforms/runtime`
- `platforms/minigame`
- `platforms/native`
- `native/tools`
- `editor/`

## 왜 CLI가 중요한가

AI가 게임을 만들려면 다음 작업을 사람 대신 안정적으로 수행해야 합니다.

- 프로젝트 상태 읽기.
- 에셋 생성과 등록.
- 씬 또는 타임라인 변경.
- 빌드와 import 동기화.
- 프리뷰 실행.
- 로그 수집.
- 실패 원인 분석.

이 작업이 모두 GUI에만 묶여 있으면 자동화가 취약합니다. CLI와 프로토콜이 있으면 작업을 기록하고 재현할 수 있습니다.

## 에디터를 버리는 것이 아니다

CLI화는 에디터를 없애는 방향이 아닙니다. 사람이 보는 UI와 AI가 호출하는 도구가 같은 상태를 공유하도록 만드는 방향입니다. 이상적인 구조는 다음과 같습니다.

- 사람: 에디터 UI와 프리뷰로 확인한다.
- AI: CLI/API/MCP/도구 호출로 작업한다.
- 시스템: 로그와 파일 diff로 실제 변경을 증명한다.

## 설계 원칙

- 도구는 실제 엔진 상태를 바꿔야 한다.
- 도구 결과는 모델이 다시 해석할 수 있어야 한다.
- UI는 도구 결과를 꾸미되, 결과를 조작하면 안 된다.
- 승인(HITL)은 위험 작업 앞에서만 명확히 개입한다.
- 실패는 숨기지 않는다.

## Speaky 포크의 문서 방향

이 사이트는 COCOS 4의 CLI/Editor 분리 흐름을 공부하면서, 게임 제작 에이전트가 실제로 필요한 도구 표면을 함께 정리합니다. 목표는 “AI가 게임을 만든다”는 구호가 아니라, 어떤 파일이 바뀌고 어떤 로그가 남는지 증명 가능한 개발 루프입니다.
