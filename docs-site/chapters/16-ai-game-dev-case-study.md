# 16. AI 게임 개발 사례

이 장은 COCOS 4 공식 기능 설명이 아니라, 실제 게임 제작 경험에서 얻은 요구사항을 COCOS 4 학습 주제로 연결하는 사례입니다. 배경 이미지, 대사, 음성, 프리뷰, 타임라인, 에셋 카탈로그를 AI가 다루려면 엔진 구조를 제대로 이해해야 합니다.

## 경험에서 확인한 문제

- 이미지 생성만으로는 게임 적용이 끝나지 않는다.
- 카탈로그에 없는 asset id를 timeline에 넣으면 편집 화면에는 보여도 실제 플레이어에서 실패할 수 있다.
- 프리뷰와 독립 플레이어가 서로 다른 리소스 경로를 볼 수 있다.
- 오디오 clip은 대사 text와 같은 timeline에 묶이되, 반복 재생/종료 조건을 분리해야 한다.
- tool call UI가 실제 호출 로그와 분리되면 사람이 AI의 행동을 신뢰하기 어렵다.

## 엔진 학습으로 바꾸면

| 제작 문제 | 엔진 주제 |
| --- | --- |
| 배경이 실제 플레이어에서 안 나옴 | Asset Manager, import/build sync, runtime resource path |
| 대사는 바뀌는데 음성이 반복됨 | Audio lifecycle, timeline event, playback state |
| 툴 호출이 가짜처럼 보임 | CLI/API 프로토콜, 로그, UI 렌더링 책임 |
| 프리뷰가 느려짐 | editor sync 정책, preview lifecycle, incremental update |
| 서브에이전트 활동이 안 보임 | event stream, trace model, persistent evidence |

## 도구 설계 원칙

AI에게 주는 도구는 “명령 이름”만 좋아서는 안 됩니다. 모델이 목적을 이해할 수 있어야 하고, 결과도 다시 판단할 수 있어야 합니다.

좋은 도구는 다음을 포함합니다.

- 입력 파라미터의 의미.
- 실제로 수정되는 파일 또는 runtime 상태.
- 성공 결과와 실패 결과의 명확한 구분.
- asset import, catalog registration, timeline insertion처럼 함께 묶여야 하는 단계.
- 사람이 승인해야 하는 위험 작업의 표시.

## UI 설계 원칙

UI는 AI의 행동을 가공해서 다른 이야기로 만들면 안 됩니다. 사람이 같이 일하려면 시간순으로 다음이 보여야 합니다.

- 사용자 메시지.
- 모델 메시지.
- 실제 도구 호출 시작.
- 실제 도구 결과.
- 서브에이전트 실행과 종료.
- 파일 diff 또는 preview 결과.

별도 요약 패널은 보조 정보일 수 있지만, 원본 흐름을 숨기면 안 됩니다.

## COCOS 4에 기대하는 연결

COCOS 4가 CLI/Editor 분리를 더 밀고 가면, AI 제작 도구는 더 안정됩니다. 에디터 버튼을 흉내 내는 자동화가 아니라, 엔진이 제공하는 명시적 도구를 호출하고 결과를 로그로 확인하는 방식이 가능해지기 때문입니다.
