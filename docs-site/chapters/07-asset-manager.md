# 07. Asset Manager

에셋은 게임 제작 자동화에서 가장 자주 깨지는 영역입니다. 이미지를 생성했지만 카탈로그에 없거나, 타임라인에는 참조가 들어갔지만 빌드된 import 파일에는 반영되지 않거나, 프리뷰에서는 보이지만 독립 플레이어에서는 보이지 않는 문제가 생깁니다.

## 확인 경로

- `cocos/asset/asset-manager`
- `cocos/asset/assets`
- `cocos/resources`에 해당하는 프로젝트 리소스 구조
- 최근 커밋 `refactor: reorganize cache-manager and asset-manager modules`

## Asset Manager에서 봐야 할 책임

- 에셋 위치 확인.
- 다운로드 또는 로딩.
- 캐시.
- dependency 추적.
- release와 lifecycle.
- 실패 상태 전달.

## No-Fallback 원칙

게임 제작 도구에서 가장 위험한 버그는 실패를 성공처럼 보이게 하는 것입니다. 배경 이미지가 없는데 기본 이미지를 대신 보여주면, 사람은 “적용됐다”고 착각합니다. 이 문서에서는 다음 원칙을 둡니다.

- 에셋이 없으면 `missing` 또는 `loadFailed`를 드러낸다.
- fallback은 명시적인 사용자 선택일 때만 사용한다.
- 테스트는 화면에 무엇이 보였는지만 보지 않고, 에셋 로그와 실제 파일 참조를 함께 본다.

## 강의 실습

1. 존재하는 이미지 경로를 로드합니다.
2. 존재하지 않는 경로를 로드합니다.
3. 두 경우의 로그, runtime 상태, 화면 결과를 비교합니다.
4. 실패가 성공 UI로 변환되는 지점이 있는지 확인합니다.

## AI 제작과의 연결

AI가 배경을 생성하는 도구는 단순히 이미지를 만드는 도구가 아닙니다. 실제 게임에 쓰려면 다음 단계가 하나의 트랜잭션처럼 묶여야 합니다.

- 이미지 생성.
- 게임 리소스 폴더에 저장.
- 카탈로그 등록.
- timeline 또는 scene clip 생성.
- 저장.
- web/native 빌드 동기화.
- 프리뷰 검증.

이 흐름을 한 도구로 묶을수록 AI는 의도를 정확히 이해합니다. 반대로 여러 도구를 순서대로 기대하면 중간 단계가 누락될 가능성이 큽니다.
